# 0.5.0: native input and screen-capture-free sessions

Pair with DiPlay 0.2.9-carLife.4-hud-test; update both apps. Direct control is opt-in and defaults off.

## Test setup

Before connecting USB, enable CarPlay direct control, DiPlay direct video and DiPlay direct audio. Changing direct control while connected closes USB; reconnect. Connect the car first so DiPlay discovers its display size, then connect/reconnect CarPlay. With direct control and video enabled, HU START makes the bridge ready without MediaProjection permission or an Android screen encoder. Enable direct audio too; system playback capture still needs recording permission in the legacy route.

Remote Touch uses native CarPlay focus highlighting. Swipes move focus; mechanical press or double tap selects; second-tap-and-slide sends wheel scrolling. Back/Home and previous/next media keys are native HID. Native scrolling depends on the focused CarPlay app; it is different from the old Accessibility finger-drag simulation. Actual HU touchscreen ACTION messages use coordinates normalized to the negotiated display. Disable direct control and reconnect USB to restore the old path.

Disable CarProjection Accessibility and test navigation, press, double tap, scrolling, Back/Home and media keys. Press Android Home and reopen the apps. Recreate the CarProjection settings Activity while connected. Disconnect/reconnect USB and check there are no stuck contacts or duplicated confirmations. Logs should show `headless ready: no screen capture` and DiPlay `CarLife input: native HID events received`.

## Implementation

Binder descriptor PcmBridge.v1 adds transaction 7 (owner + live flag -> bounded four-int commands) and 8 (owner release), with the existing package UID check. One consumer owns a one-second lease. Queue overflow first sends RESET; a lost touch chain cannot resume on MOVE. Polling runs on a dedicated 16ms worker; HID batches use the existing ordered input executor with at most one outstanding batch. USB parsing does not wait for the HID network writer.

CarPlayController owns the input bridge independently of its Activity. CarProjection's connected-device foreground service owns the MsgProcess session and accessory descriptor, handles USB detach without UI, and holds a renewed CPU wake lock. MsgProcess stores application context and a weak UI Activity; destroying the UI detaches callbacks and preserves a connected session. The legacy permission dialog still needs an Activity. A fresh accessory still enters through the Activity permission/attach flow; process death and force stop do not restore the session.

The established audio conversion and video heartbeat remain. This release does not add vehicle microphone uplink or Linux AOA. Native focus/wheel compatibility and the service lifetime require physical testing; successful writes do not prove the iPhone accepted an input.

## Checks

JVM tests cover focus steps, jitter, double-tap select/scroll, mechanical deduplication, bounded queue overflow, contact reset and lost touch chains. Actions builds/lints both apps and runs DiPlay suites. Physical validation is pending.
