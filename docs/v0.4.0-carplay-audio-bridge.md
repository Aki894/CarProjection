# 0.4.0 — direct DiPlay audio experiment

The existing Android → CarLife baseline stays available. This version adds an
opt-in **DiPlay 直接音频（实验）** switch and a local Binder PCM receiver.
Use the paired bridge build from [Aki894/DiPlay](https://github.com/Aki894/DiPlay).
Full installation/build notes: [CarLife bridge](https://github.com/Aki894/DiPlay/blob/main/docs/CARLIFE-BRIDGE.md).

When enabled, system playback capture stops. DiPlay decoded PCM is mixed, voice
ducks music to 25%, and the existing TTS output uses the selected rate (48k mono
default) and car volume gain. No MEDIA channel is used for direct audio. Video
and accessibility touch continue through the current projection path.

The service only accepts installed DiPlay package UIDs (`com.shihab.diplay` and
`com.shihab.diplay.hudtest`) and rejects inactive USB/projection sessions. It is
package-authorized, not certificate-pinned. Binder carries control/file descriptors;
PCM uses pipes, not large Binder parcels or network sockets. Receiver queues hold
at most 120ms per stream and six streams. USB/mode changes clear old audio; idle
TTS sessions end after 500ms. Music starts with a 40ms prebuffer; incomplete
AAC tails wait briefly for the next decoded frame rather than adding silence. `[BRIDGE]` logs survive input-log filtering/export.

Check music, navigation, phone-speaker silence, car volume 0/30/100, rapid touch/back,
switch-off comparison, peer termination, and separate iPhone/USB reconnects on the car.
Unit tests cover split PCM, ducking, clipping, queue bounds, tail draining and reset.
Build/lint checks cannot establish physical audio routing, wireless behavior or timing.
Direct H.264/HID, car microphone uplink and service-owned USB are later milestones.
