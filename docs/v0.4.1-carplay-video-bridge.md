# 0.4.1 — direct H.264 and car display negotiation

Install together with DiPlay 0.2.9-carLife.2-hud-test. First connect the phone to
Lexus and enable **DiPlay 直接视频（实验）**, then open DiPlay CarLife and connect
iPhone. If DiPlay was connected first, reconnect CarPlay after the car target is
reported. The audio experiment remains an independent opt-in switch.

CarProjection publishes HU VIDEO_ENCODER_INIT width/height and selected FPS.
DiPlay advertises exactly that main-screen canvas, H.264 and a full safe area;
phone resolution, resolution percentage, HEVC preference and canvas enlargement
are bypassed for this negotiated session, without changing saved preferences.
Local preview keeps the same canvas with aspect-preserving fit on the phone.
Physical car screen dimensions are not inferred from pixel dimensions.

ScreenStream decrypted main video (type 110) already reaches AndroidMediaSink as
Annex B. avcC is strictly converted to SPS/PPS and its SPS visible dimensions
(including cropping) must match the car target. Auxiliary screen 111 is never
forwarded. A local authenticated Binder exchanges status and pipe descriptors;
records are big-endian kind + length + body, kind 1 Annex B SPS/PPS, kind 2 one
Annex B access unit. Limits: 64KiB config, 2MiB frame, six pending sender frames
and 2MiB sender bytes, existing eight-frame/2MiB USB backlog. Aged/overflowed
sender frames discard the dependent chain and request a new IDR. Receiver USB
backpressure also signals a rate-limited CarPlay keyframe request through status.
Each IDR includes SPS/PPS. Local decoding and the projection encoder remain
running for preview, existing accessibility controls and immediate fallback.
Only one video source may enqueue USB frames; source epochs discard old queued
packets when switching. An already writing packet finishes before the next source.

Logs: `video SPS/PPS accepted=WxH`, `video direct active=WxH H.264`, then
`video USB sent frames=N bytes=N` proves the new path wrote packets; queued
counts alone do not. A real image on the car is still required to establish HU
codec compatibility. Disable the video switch if the HU is black/corrupt: USB
write success cannot detect a decoder rejecting profile/level/bitrate. Unsupported
codec, wrong SPS dimensions, pipe closure and USB/projection loss fall back to
screen projection; reconnection starts from an IDR.

Direct video intentionally excludes Android UI, notifications and cursor overlay.
Remote Touch still follows the existing phone accessibility path in this step:
keep DiPlay's CarPlay screen foreground; phone content fitting can change the
pointer-to-car mapping. CarPlay HID and a car-visible pointer are later work.
This version does not promise zero local decoding/encoding work or car microphone.

Check aspect ratio, circles/icons, maps, music + navigation audio, rapid swipes,
video-only and audio-only switch combinations, off/on and USB/iPhone reconnects.
Export CarProjection logs for rejected SPS, car target and USB sent counters.
