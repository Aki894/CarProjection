## 日志结论

分析用户提供的 `CarProjection-0.3.6-20261002-142751.txt`（5542 行，Android 12 / HUAWEI JEF-AN20）。日志不是 v0.3.8，不能用它评价新光标绘制的实车表现。

- 保留了 12 次 `resetUsb`，但异常只通过 `printStackTrace` 写入系统日志，导出文件无法区分读失败、写失败、主动关闭。
- 14:18:25.734 收到 BACK，14:18:26.274 重置，间隔 0.540 秒；14:20:16.530 收到 BACK，14:20:17.061 重置，间隔 0.531 秒。也有其他 BACK 后未立刻断开的记录。该规律与回到本应用后再返回、Activity 销毁并释放 USB 的代码路径高度一致，但旧日志没有 onDestroy 证据，不能断言这两次已被完全归因。
- 导出文件内有 17 条 DETACHED 广播，其中 14:17:02.860–02.892 约 32 ms 出现 7 次。默认 standard Activity 可被多次创建，每个实例各自注册广播、持有连接，代码层面确实存在问题；广播重复是否全部来自多实例，需要新版本实例 ID 验证。
- DETACHED 说明系统报告 USB 配件离开，不能单凭它区分插头接触不良、线缆、电源或车机主动重新枚举。移动手机更容易触发，支持用户对接触不良的怀疑，软件修复不能替代物理链路排查。
- 14:17:01.018 音频 dropped=0，成功发送与入队字节匹配。这一时点未见音频积压；旧版没有视频队列计数，不能据此排除视频积压。
- 最初日志中的 16 kHz INIT 是当时会话，导出头部是导出时所选 48 kHz，二者不等于同一时刻的配置。

## 验证

## 实车验证顺序

1. 使用固定签名 APK 覆盖安装，不必清除设置。正常连接后，在本应用主页和其他应用分别连续返回，确认连接保留。
2. 手机固定不动，先不开音乐，以 30 fps/3 Mbps 快滑与连续 Back 测试；再开 48 kHz 单声道音频复测。不要一次同时改变帧率、码率和音频选项。
3. 比较现有线与已知正常的数据线。若日常挪动旧手机会断，观察系统 DETACHED 与 READ/WRITE 时间；不必反复晃动磨损接口。
4. 重连按钮可能取决于车机是否重新握手；失败再物理重插。覆盖授权中断、通知停止、多次插拔、切歌键及旧会话恢复。授权弹窗中途断连时，请先关闭旧弹窗，再手动重连，避免同时申请多份投屏授权。
5. 断连后立即导出日志，提供事发操作与大致时间；寻找 `[USB] CLOSE reason=...`、`[LIFECYCLE]`、`[VIDEO] backlog`。保留最近断开原因至设置中，重启后仍可见；完整日志仍为当前进程内记录。

## 阶段一范围与后续

目前已具备 Android → CarLife 的视频、TTS 单声道音乐/音量调节、Remote Touch 光标/双 tap/拖拽、节能及诊断链路，可作为 carlife2carplay 的阶段一功能基线。稳定性回归尚未完成；这不等于已实现 CarPlay。

当前传输仍由 Activity 持有，进程被系统终止、活动因未覆盖的配置变化重建时仍会停止。要进一步支持长期无人值守恢复，后续应把传输及会话状态迁入服务、设计明确的恢复状态机，并验证 Android 14+ 每次投屏授权约束。此次不冒然大改所有者架构。

其余边界：此 Lexus 的 MEDIA 通道未证实可用、TTS 无立体声；PlaybackCapture 不独占路由且受源应用策略限制；车机/手机/线缆跨设备兼容性、全屏透明光标层与端到端延迟仍需真实设备回归。现有 root 辅助工具方法不再被活动的切歌路径调用，后续可单独整理历史工具代码。
