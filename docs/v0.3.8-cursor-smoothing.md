# v0.3.8：触控板光标刷新与响应优化

## 改动

- 光标由移动小悬浮窗口改为在固定透明、不可触摸的无障碍悬浮层内绘制；坐标保留浮点精度。每个 MOVE 不再触发 WindowManager.updateViewLayout 或查询屏幕尺寸。
- 绘制按手机显示帧调度，同一帧内多次输入合并绘制，所有原始位移仍按顺序计算，加速度不因合并而改变。
- 默认开启“光标平滑”：普通移动采用 24 ms 视觉过渡，不预测、不额外增加移动距离。新输入从当前视觉位置继续，最后一个目标在 24 ms 后的首个可用显示帧到达，停下后不持续刷新。
- 按下、抬起及点击会同步视觉和完整输入目标，拖拽候选/拖拽期间直接使用目标坐标。double tap、机械 OK 去重、双 tap + 滑动及拖拽锁光标规则保留。
- MOVE 保留一条包含 dx/dy/ts 的完整解析日志，省去此前每包五条重复原始数据日志；移动先交给控制器，再记录日志。日志 UI 通知合并，完整日志记录和导出保留。
- “光标平滑”关闭时使用直接目标坐标，同样按显示帧刷新。采样率默认 48 kHz 单声道和音量调节保留。

## 实车复测

1. 对比平滑开启/关闭：慢速斜线、小范围微调、连续快移、反向和边缘，检查跳格、跟手及残影。
2. 移动后立即机械 OK / double tap，确认点击目标；复测双 tap + 滑动及锁光标模式。
3. 手机直接触摸底层应用，确认悬浮层不挡触摸；测试横竖屏切换及 USB 重连，确认位置正常。
4. 如果手机画面较平滑而车机仍明显跳格，对比投屏 30/60 fps（保存后重连）；实际效果仍受车机解码、触控板发包频率和投屏延迟限制。本版没有自动修改投屏帧率。

24 ms 是视觉过渡参数，不代表端到端延迟保证。当前版本已通过 JVM 光标运动、音频、诊断及手势检查；最终流畅度与全屏透明层的实际设备表现需要实车确认。
