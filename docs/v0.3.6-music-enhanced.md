# v0.3.6：TTS 音质组合测试

versionCode 18，保留软件输出音量、双 tap 和日志导出。

## 可组合规格

| 采样率 | 单声道 | 双声道 |
|---|---|---|
| 16 kHz | 已实车验证，默认 | 待验证 |
| 24 kHz | 待验证 | 待验证 |
| 32 kHz | 待验证 | 待验证 |
| 44.1 kHz | 待验证 | 待验证 |
| 48 kHz | 待验证 | 待验证 |

采样格式均为 PCM16，小端；采样率与声道数两个下拉选项组成 10 种组合。仅在 TTS 兼容模式开启时可编辑，默认 16 kHz 单声道。全部仍走 channel 4，不使用 MEDIA channel 3。

TTS INIT 的 sampleRate/channelConfig/sampleFormat 是整数字段，proto 未固定为 16 kHz 单声道，但这不证明具体车机能处理全部组合。解码器可能不支持、忽略参数或按固定规格播放。

## 实现

- 16 kHz 单声道：保留原来已验证的混音、63-tap 低通与 3:1 重采样实现。
- 48 kHz 双声道：保留原始捕获 PCM，不降采样。
- 48 kHz 单声道：左右平均混音，保持采样率。
- 其他格式：63-tap 低通滤波，整数相位累加器控制输出采样数，必要时插值；44.1 kHz 使用 147/160 比例，保留跨读取块的相位和帧边界。
- 输出积累为 20 ms 一个包，软件音量使用对应的声道数按帧处理。
- 选择立即生效，先 END 旧 TTS 会话，再 INIT 新规格；设置自动保存。
- 新增「TTS 选中规格测试音（实验）」：按当前组合发送 2 秒、1 kHz 测试音，再恢复当前实时捕获格式。保留独立的「TTS 16 kHz 测试音」作为固定基准。
- 导出头部记录选择规格，INIT 日志记录实际 rate/channels。

## 测试建议

先调低「车机输出音量」，在 TTS 兼容模式下选规格并点「TTS 选中规格测试音」。每种有声组合还应播放实际音乐，检查速度、音调、失真与稳定性。测试音有声不等于车机准确识别格式。

建议先用单声道按 16 → 24 → 32 → 44.1 → 48 kHz 测试采样率；再对可用采样率测试双声道。也可先测 16 kHz 双声道，单独判断声道支持。

无声或异常时手动选回 16 kHz 单声道；如果车机未恢复，拔插 USB 重连。程序无法检测扬声器是否实际发声，因此没有自动失败回退。

输出 PCM 数据量：采样率 × 声道数 × 2 字节/秒，范围 32 KB/s 至 192 KB/s，待发送包限制仍为 8。

## 自动验证边界

JDK 检查覆盖全部 10 种转换的输出计数、跨任意字节块的一致性、声道独立、1 kHz 增益、48 kHz 双声道的字节一致性、16 kHz 基准一致性，以及 44.1 kHz 一分钟输入的采样数量。还运行此前音量、手势、USB、日志检查。Android 构建由 GitHub Actions 验证。

实际车机可接受的格式与听感需要设备测试。本版本用于探索高规格 TTS 输出，并非 EQ、高频生成或音频超分辨率。
